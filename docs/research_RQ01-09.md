## RQ-01: Thompson-Barnett COULCCアルゴリズムの数学的導出

### Coulomb波動方程式と基本定義

Coulomb波動方程式は以下で定義される（DLMF §33.2）:

```
d²w/dρ² + [1 − 2η/ρ − ℓ(ℓ+1)/ρ²] w = 0
```

**正則解** F_ℓ(η,ρ) と **非正則解** G_ℓ(η,ρ) に対し、出射波は H_ℓ⁺ = G_ℓ + iF_ℓ、H_ℓ⁻ = G_ℓ − iF_ℓ で構成される。**Wronskian関係** は W{G_ℓ, F_ℓ} = G_ℓ F'_ℓ − G'_ℓ F_ℓ = 1 であり、これがCF1とCF2の結果を結合する鍵となる。古典的転回点は **ρ_tp(η,ℓ) = η + √(η² + ℓ(ℓ+1))** で与えられる。

### CF1（実数連分数）: f_ℓ = F'_ℓ/F_ℓ の計算

DLMF §33.8 Eq.33.8.1に基づく。補助量を次のように定義する:

```
R_ℓ = √(1 + η²/ℓ²)
S_ℓ = ℓ/ρ + η/ℓ
T_ℓ = S_ℓ + S_{ℓ+1}
```

CF1は標準連分数 b₀ + a₁/(b₁ + a₂/(b₂ + ...)) の形式を持ち、**部分分子**と**部分分母**は:

- **b₀ = S_{ℓ+1}**
- **n ≥ 1 に対し: aₙ = −R²_{ℓ+n}**（部分分子）
- **n ≥ 1 に対し: bₙ = T_{ℓ+n}**（部分分母）

展開すると:

```
T_{ℓ+n} = (ℓ+n)/ρ + η/(ℓ+n) + (ℓ+n+1)/ρ + η/(ℓ+n+1)
R²_{ℓ+n} = 1 + η²/(ℓ+n)²
```

CF1は全ての有限ρで収束し、収束に約 |ρ| 回の反復を要する。

### CF2（複素連分数）: H_ℓ⁺'/H_ℓ⁺ = p + iq の計算

DLMF §33.8 Eq.33.8.2に基づく。定数を a = 1+ℓ+iη, b = −ℓ+iη, c = i(1−η/ρ) と定義し:

- **b₀ = c = i(1 − η/ρ)**
- **n ≥ 1 に対し: aₙ = (n+ℓ+iη)(n−1−ℓ+iη)**
- **n ≥ 1 に対し: bₙ = 2(ρ − η + ni)**

CF2は ρ ≠ 0 で収束する。|ρ| が大きいほど収束は速く、|ρ| < 0.5 では収束が極めて遅いため他の方法（べき級数）が必要となる。

### 修正Lentz法（Lentz-Thompson-Barnett法）の擬似コード

```
FUNCTION evaluate_CF(a[], b[], ε):
    small ← 1.0e-50        // ゼロ除算回避用の微小値
    h₀ ← b₀
    IF (h₀ == 0) THEN h₀ ← small
    D₀ ← 0;  C₀ ← h₀

    FOR n = 1, 2, ..., N_max DO:
        Dₙ ← bₙ + aₙ · D_{n-1}
        IF (Dₙ == 0) THEN Dₙ ← small
        Cₙ ← bₙ + aₙ / C_{n-1}
        IF (Cₙ == 0) THEN Cₙ ← small
        Dₙ ← 1 / Dₙ
        Δₙ ← Cₙ · Dₙ
        hₙ ← h_{n-1} · Δₙ
        IF (|Δₙ − 1| < ε) THEN RETURN hₙ   // 収束判定
    END FOR
    RETURN hₙ  // 未収束
```

**実装上の要点**: smallは ε × |bₙ| 程度より十分小さい値（例: 10⁻⁵⁰）。CₙとDₙの両方がゼロに近づく場合を監視し、smallで置換する。収束判定 |Δₙ − 1| < ε は |hₙ/h_{n-1} − 1| < ε に等価。実数・複素数の両方に適用可能。

### Wronskian結合: CF1とCF2の結果からF, G, F', G'を算出

CF1から u = F'_ℓ/F_ℓ を、CF2から p + iq = H_ℓ⁺'/H_ℓ⁺ を得た後（Steed法、DLMF §33.8 Eqs.33.8.4-5）:

```
F_ℓ  = ± [q⁻¹ · ((u−p)² + q²)]^{−1/2}
F'_ℓ = u · F_ℓ
G_ℓ  = q⁻¹ · (u − p) · F_ℓ
G'_ℓ = q⁻¹ · (u·p − p² − q²) · F_ℓ
```

符号 ± はCF1の最終収束値の符号と一致させる。

### 三項漸化式（DLMF §33.4）

任意のCoulomb関数 X_ℓ（F_ℓ, G_ℓ, H_ℓ± のいずれか）に対し:

```
R_ℓ · X_{ℓ-1} − T_ℓ · X_ℓ + R_{ℓ+1} · X_{ℓ+1} = 0
```

微分関係は:

```
X'_ℓ = R_ℓ · X_{ℓ-1} − S_ℓ · X_ℓ         (ℓ ≥ 1)
X'_ℓ = S_{ℓ+1} · X_ℓ − R_{ℓ+1} · X_{ℓ+1}  (ℓ ≥ 0)
```

**安定性**: F_ℓ は **下降漸化**（ℓ減少方向）が安定（F_ℓは ℓ→∞ で最小解）。G_ℓ および H± は **上昇漸化**（ℓ増加方向）が安定。

### べき級数展開（小ρ）

```
F_ℓ(η,ρ) = C_ℓ(η) · ρ^{ℓ+1} · Σ_{k=0}^∞ A_k · ρ^k
```

**係数の漸化式**:

```
A₀ = 1,  A₁ = η/(ℓ+1)
A_k = [2η·A_{k-1} − A_{k-2}] / [k(2ℓ+1+k)]   (k ≥ 2)
```

**規格化定数 C_ℓ(η)** の漸化式:

```
C₀(η) = √(2πη/(e^{2πη} − 1))
C_ℓ(η) = C_{ℓ-1}(η) · √(ℓ² + η²) / [ℓ(2ℓ+1)]
```

₁F₁級数は全ての有限ρで収束するが、実用的には |ρ| ≲ max(1, 2|η|) が限界（壊滅的桁落ちのため）。

### 6つの計算領域と境界判定

COULCCは6つのケースで絶対規格化を行う:

| ケース | 方法 | 条件 |
|--------|------|------|
| 1 | ₁F₁べき級数からF | 中程度 |ρ|、転回点内部 |
| 2 | CF2(+)とCF2(−)の両方 | 複素ρ,η |
| 3 | Steed法（実ρ,ηの共役利用） | **実ρ,η: 最も効率的** |
| 4 | ₂F₀漸近展開 + Padé加速 | |ρ| ≫ |η|² + |λ| |
| 5 | F_ℓとF_{ℓ'=−ℓ−1}からH^ω | |ρ| < 0.5、非整数ℓ |
| 6 | 対数表現（L'Hôpital） | |ρ| < 0.5、整数ℓ |

**境界基準**: |ρ| < 0.5 → ケース5/6、実ρ,η かつ |ρ| > 0.5 → ケース3、大 |ρ| → ケース4。CF1AとCF1の切替は |ρ| > ASYM × C_λA（ASYM = 3.0）で判定。

### Coulomb位相差 σ_ℓ = arg[Γ(ℓ+1+iη)] の計算

**Stirling漸近展開** ln Γ(z) ∼ z·ln(z) − z + ½·ln(2π/z) + Σ B_{2n}/[2n(2n−1)z^{2n−1}] の係数:

| n | B_{2n}/[2n(2n−1)] |
|---|---|
| 1 | 1/12 |
| 2 | −1/360 |
| 3 | 1/1260 |
| 4 | −1/1680 |
| 5 | 1/1188 |
| 6 | −691/360360 |

小 |z| では漸化式 ln Γ(z+1) = ln Γ(z) + ln(z) でシフトしてからStirlingを適用する。**C_ℓ(η)** も対数ガンマ経由で計算: C_ℓ(η) = 2^ℓ · exp(−πη/2 + [ln Γ(1+ℓ+iη) + ln Γ(1+ℓ−iη)]/2 − ln Γ(2ℓ+2))。

### 禁止領域の処理と指数スケーリング

ρ < ρ_tp ではF_ℓ ∼ e^{−κρ}（アンダーフロー）、G_ℓ ∼ e^{+κρ}（オーバーフロー）となる。**COULCCのMODEパラメータ**でスケーリングを制御:

- MODE = 1: 通常（非スケーリング）
- MODE = 2: F̃_ℓ = F_ℓ · e^{+Im(θ)}, G̃_ℓ = G_ℓ · e^{−Im(θ)} を返す

**ρシフト戦略**: CF2が禁止領域で収束しない場合、ρ → ρ' = ρ + Δρ（ρ' > ρ_tp）にシフトしてCF2を評価し、Coulomb ODEを逆方向に積分してρでの値を得る。|ρ| < 0.5 では₁F₁級数（ケース1/5/6）を直接使用する。

## RQ-03: mpmath検証データの生成方法

### mpmathのCoulomb関数アルゴリズム

mpmathは **合流型超幾何関数（₁F₁）表現** を使用する。F_ℓ(η,ρ) = C_ℓ(η) · ρ^{ℓ+1} · e^{−iρ} · ₁F₁(ℓ+1−iη; 2ℓ+2; 2iρ) を `hypercomb` フレームワークで評価する。このフレームワークは**桁落ち検出時に内部精度を自動的に増加**し、極でのキャンセレーションをperturbationで処理する。Fredrik Johanssonの設計思想: 「Coulomb波動関数の数値計算は困難であり、任意精度演算が事実上不可欠」。

### σ_ℓの計算方法

**推奨**: `mpmath.im(mpmath.loggamma(l+1+1j*eta))` を使用する。`loggamma` は主値枝を正しく計算し、巻き付き情報を保持する。`mpmath.arg(mpmath.gamma(...))` は大引数でオーバーフロー/情報喪失の危険があるため**非推奨**。

### 50桁精度の設定と計算時間

```python
mpmath.mp.dps = 60  # 50桁の安全マージンとして60を設定
```

gmpy2がインストールされていれば dps=50 で約 **2–3倍の高速化**。計算時間の目安:

| dps | 1回あたりの時間（標準パラメータ） |
|-----|-------------------------------|
| 15 | 1–7 ms |
| 50 | 20–200 ms |
| 100 | 0.1–2秒 |

η >> 1 かつ ρ << η の準古典的領域では**桁落ちにより計算時間が大幅に増加**する可能性がある（dps=70–100推奨）。入力パラメータは文字列で指定すべき（例: `mpmath.mpf('0.1')`）。

### 推奨テストグリッド

**Tier 1（標準検証）**: (l=0, η=0, ρ=1) → ベッセル極限でF₀=sin(ρ)、(l=2, η=1.5, ρ=3.5)、(l=0, η=1, ρ=5) → A&S表との比較。

**Tier 2（困難ケース）**: (l=0, η=10, ρ=1) → 深い禁止領域（G₀≈3.09×10⁹）、(l=0, η=100, ρ=1) → 極端な禁止領域、(l=0, η=100, ρ=200) → 転回点近傍。

**Tier 3（高角運動量）**: (l=10, η=5, ρ=1)、(l=30, η=10, ρ=100)。

**自己整合性検証**: Wronskian F'G − FG' = 1、交差積 F_{ℓ-1}G_ℓ − F_ℓG_{ℓ-1} = ℓ/√(ℓ²+η²)、微分方程式の満足度、異精度間比較（dps=70 vs dps=100で50桁の一致を確認）。

## RQ-04: 幅揺らぎ補正（WFC）のMoldauer実装詳細

### Moldauer形式の中核公式

WFC付きHauser-Feshbach断面積:

```
⟨σ_ab^fl⟩ = (π/k²_a) · g_a · (T_a · T_b / Σ_c T_c) · W_ab
```

**Moldauerの幅揺らぎ補正因子 W_ab** は1次元積分で表される:

```
W_ab = (1 + 2δ_ab/ν_a) × ∫₀^∞ dt × [F_a(t) · F_b(t)] / Π_k F_k(t)^{ν_k/2}
```

ここで F_k(t) = 1 + (2/ν_k) · (T_k / Σ_c T_c) · t。Kroneckerデルタ δ_ab による因子 (1 + 2δ_ab/ν_a) が**弾性散乱増強**を与える。

### 弾性散乱増強因子と自由度パラメータ ν_a

弾性散乱増強因子 W_a と ν_a の関係: **ν_a = 2/(W_a − 1)**。

極限値: 孤立共鳴（T → 0）で W_a → 3（ν_a → 1、Porter-Thomas極限）、多数重畳チャンネル（T大）で W_a → 2（ν_a → 2、GOE予測）。

**Kawano-Talou（LANL, 2016）の最新パラメータ化**（GOEへの最良フィット）:

```
ν_a = 1 / [1 + α(T_a) · F · G]
F = (T_a + T) / (1 − T_a)
G = 1 + 2.5 · T_a · (1 − T_a) · exp(−2T)
α(T_a) = 0.02879 · T_a + 0.2459
```

### THW形式との主要な違い

| 特徴 | HRTW | Moldauer |
|------|------|---------|
| 理論的基盤 | 統計的K行列 | 統計的S行列シミュレーション |
| WFC適用 | 弾性チャンネルのみ明示的 | 全チャンネルに積分で適用 |
| 計算手法 | 反復法（V_c の自己無撞着決定） | **直接数値求積** |
| GOEとの偏差 | ~3.1% (std dev) | ~2.8%（LANL改良版） |

### GOE三重積分（VWZ公式）

Verbaarschot-Weidenmüller-Zirnbauer (1985, Phys. Rep. 129, 367) の厳密公式:

```
⟨S_ab S*_cd⟩_fl = (1/8) ∫₀^∞ dλ₁ ∫₀^∞ dλ₂ ∫₀^1 dλ × μ(λ,λ₁,λ₂) × Π_c [...] × J(λ,λ₁,λ₂)
```

λ₁ = λ₂ で可積分特異点があり、適応的ガウス求積法が必要。**Moldauer単一積分の10³–10⁴倍遅い**。TALYSでは Gauss-Laguerre求積法で20–32点で実装。

### WFCが重要となる定量的条件

**T = Σ_c T_c < 5**（開放チャンネル数が少ない）場合にWFCは顕著。具体的には: 中重核で閾値から **2–4 MeV**、アクチノイドでは閾値から **1–2 MeV** の範囲。開放チャンネル数5未満ではW_a = 2.0–2.5、弾性チャンネルに20–30%の増強効果。T > 5 では各手法間の差は1%未満。

## RQ-05: Brune変換の数値実装

### 標準Lane-Thomas → Brune変換の核心公式

Brune代替エネルギー **Ẽ_λ** は**非線形固有値問題**の解:

```
E(Ẽ_λ) · a_λ = Ẽ_λ · a_λ
ここで E_{λμ}(E) = E_λ δ_{λμ} − Σ_c γ_{λc} γ_{μc} [S_c(E) − B_c]
```

S_c がエネルギーに依存するため、**反復解法**が必要（Newton法または二分法）。収束後、**代替換算幅振幅** γ̃_{λc} = Σ_μ a_{μλ} γ_{μc}（固有ベクトルaによる直交回転）。

### Brune形式での衝突行列の直接構成

```
(Ã⁻¹)_{λμ} = (Ẽ_λ − E)δ_{λμ} − Σ_c γ̃_{λc} γ̃_{μc} [S_c(E) − S_c(Ẽ_λ)] − (i/2) · 2Σ_c γ̃_{λc} P_c γ̃_{μc}
```

**重要**: シフト項は S_c(E) − S_c(Ẽ_λ) であり、E = Ẽ_λ でゼロになる → **共鳴位置でレベルシフトが消滅**する。

### 準位シフト関数 S_c(E) とその微分

```
L_c(ρ) = ρ · O'_ℓ/O_ℓ = S_c + iP_c
```

中性子チャンネル（η=0）の具体例: S₀ = 0, P₀ = ρ; S₁ = −1 + ρ²/(1+ρ²), P₁ = ρ³/(1+ρ²)。

**dS_c/dE の安定な計算**: AZURE2はGSL（GNU Scientific Library）の数値微分ルーチンを使用。解析的計算はCoulomb関数の漸化式経由で可能だが、有限差分法 dS/dE ≈ [S(E+δ) − S(E−δ)]/(2δ) も実用的。

### AZURE2での実装

AZURE2（C++、GPL-3.0、GitHub: rdeboer1/AZURE2）は**Brune基底をデフォルト**で使用する（Brune本人の2024年IAEA講演で確認）。GSLを使用してCoulomb関数F_ℓ, G_ℓとその微分を計算し、固有値問題を反復的に解いてBruneパラメータを決定する。

### Brune変換が特に有利なケース

**広い共鳴**: レベルシフト Σ_c γ²_{λc} S'_c が大きく、形式的 E_λ と観測位置が大きく異なる場合。**重畳共鳴**: 固有値問題による多準位一般化が正確に準位混合を処理。**閾値効果**: S_c が急変する閾値近傍で自然に処理。**パラメータ相関の低減**: ベイズ解析（BRICK/AZURE2）でのフィッティングに有利。

## RQ-06: cudarc最新APIと使用パターン

### 最新バージョンと主要API変更

**cudarc v0.19.3**（2026年3月時点の最新安定版）。リポジトリは chelsea0x3b/cudarc（旧 coreylowman/cudarc）に移行。**最大の破壊的変更**: `CudaDevice` 中心のAPI → **`CudaContext` + `CudaStream`** APIへの移行（v0.16+）。

### 基本パターン（コンテキスト → モジュール → カーネル起動）

```rust
use cudarc::driver::{CudaContext, LaunchConfig};
use cudarc::nvrtc::compile_ptx;

// 1. コンテキスト作成
let ctx = CudaContext::new(0)?;
let stream = ctx.default_stream();

// 2. デバイスメモリ確保・転送
let inp = stream.clone_htod(&[1.0f64; 100])?;
let mut out = stream.alloc_zeros::<f64>(100)?;

// 3. NVRTCでPTXコンパイル
let ptx = compile_ptx("extern \"C\" __global__ void kern(...) {...}")?;

// 4. モジュールロード → カーネル起動
let module = ctx.load_module(ptx)?;
let func = module.load_function("kern")?;
unsafe {
    stream.launch_builder(&func)
        .arg(&mut out).arg(&inp).arg(&100usize)
        .launch(LaunchConfig::for_num_elems(100))?;
}

// 5. 結果をホストにコピー
let result: Vec<f64> = stream.clone_dtoh(&out)?;
```

### cuBLAS経由のbatched zgetrf/zgetrs

cuBLASのsafe APIは**GEMM/GEMVに限定**されており、zgetrfBatchedのsafeラッパーは存在しない。代替手段:

- **推奨: cuSOLVER** (`cudarc::cusolver::safe`): cusolverDnZgetrf/Zgetrsをサポート
- **FFI直接利用**: `cudarc::cublas::sys::cublasZgetrfBatched` で生FFI呼び出し
- batched操作はcuBLASの `sys` または `result` レベルでアクセス可能

### スレッド安全性

`CudaContext`, `CudaSlice<T>`, `CudaStream`, `CudaBlas` はすべて **Send + Sync**。`CudaSlice<T>` は `Arc<CudaContext>` を所有し、RustのRAIIでメモリ管理。`CudaView`/`CudaViewMut` は借用チェッカーで安全性を保証。

### CudaStreamによる非同期実行

```rust
let stream1 = ctx.new_stream()?;
let stream2 = ctx.new_stream()?;
// 異なるストリームでカーネルを同時実行
unsafe {
    stream1.launch_builder(&kernel).arg(&mut data1).launch(cfg)?;
    stream2.launch_builder(&kernel).arg(&mut data2).launch(cfg)?;
}
stream1.synchronize()?;
stream2.synchronize()?;
```

CUDA Graphsもサポートされ、反復実行のオーバーヘッドを最小化可能。

### Burnフレームワークの使用パターン

`burn-cuda` クレートは CubeCL + cudarc で構成。CubeCLの `#[cube]` マクロがRustからCUDA C++コードを生成 → cudarc の `nvrtc::compile_ptx()` でPTXに変換 → `CudaContext::load_module()` でロード → `CudaStream::launch_builder()` で起動。

## RQ-07: 結合チャンネル光学模型の数値手法

### 結合チャンネルSchrödinger方程式の行列形式

N結合チャンネルの動径方程式:

```
d²u(R)/dR² = W(R) · u(R)
```

ここで W(R) は N×N 行列で W_{cc'} = (2μ/ℏ²)[V^{J_T}_{cc'}(R) + δ_{cc'}(L_c(L_c+1)ℏ²/(2μR²) + V(R) − iW(R) + ε_c − E)]。完全なS行列を得るにはN個の線形独立解を同時伝播し、N×N解行列 Y(R) を構成する必要がある。

### 行列Numerov法

```
T_{n+1} Y_{n+1} = (2I − 10h²/12 · W_n) Y_n − T_{n-1} Y_{n-1}
ここで T_n = I + h²/12 · W_n
```

各ステップでO(N³)の演算（行列乗算＋T_{n+1}の逆行列）が必要。閉チャンネルの指数的成長に対する数値不安定性があるため、**Johnson再規格化Numerov法**（比行列 R_n = Y_n Y_{n-1}⁻¹ を伝播）が実用的。

### Johnson対数微分法（結合チャンネルへの拡張）

N×N対数微分行列 Z(R) = Y'(R) Y(R)⁻¹ を伝播。**行列Riccati方程式** Z'(R) = W(R) − Z(R)² を満たす。区分定数ポテンシャル近似で:

```
Z_{n+1} = Q_n − (Q_n + Z_n)⁻¹ Q_n²
ここで Q_n = W_n^{1/2} cot(h W_n^{1/2})
```

**利点**: 無条件数値安定性（閉チャンネルの指数成長なし）、再直交化不要、O(N³)/ステップ。改良版にManolopoulos (1986) の参照ポテンシャル法がある。

### ECIS-06のアルゴリズム

ECIS（Raynal, CEA-N-2772, 1994）は **逐次反復法** を採用。全チャンネルを同時積分するのではなく、チャンネルを順序付けて各方程式を逐次的に解く。Padé近似で収束加速。計算効率は全方程式数/基底状態関連方程式数の比に比例し、大規模問題で直接積分より遥かに高速。

### 変形パラメータから結合行列要素への変換

軸対称変形核の表面半径 R(θ) = R₀[1 + Σ_λ β_λ Y_{λ0}(θ)]。結合ポテンシャルの行列要素:

```
V^{J_T}_{cc'}(R) = Σ_λ (−1)^{L'+I+J_T} f_λ(R) ⟨L‖Y_λ‖L'⟩ ⟨nI‖T_λ‖n'I'⟩ {J_T I L; λ L' I'}
```

1次結合の動径形状因子: f_λ^{(1)}(R) = −β_λ R₀ dV/dR|_{R=R₀}。2次結合（β₂²項）は Y_{λ₁0}Y_{λ₂0} のClebsch-Gordan結合を含む。

### 計算コストのスケーリング

全手法（Numerov, 対数微分, R行列）で **O(N³) /動径ステップ**。典型的なN値: 偶偶核基底帯のみで4–8、β₂+β₄で10–20、アクチノイド5バンド結合で30–80、CDCC（弱束縛核）で100–500。2026年1月のJóźwiak et al. (arXiv:2601.01159) は **WISEアルゴリズム** でO(N²)スケーリングを達成（S行列の単一列計算に限定）。

## RQ-08: GPU上のCoulomb関数計算

### 修正Lentz法のCUDA実装可能性

各スレッドが独立にCoulomb関数を評価する**embarrassingly parallel**構造は原理的に実現可能。主な課題は **ワープ発散**: 異なるスレッドが異なる反復回数を必要とし、ワープ内の最遅スレッドに合わせて全スレッドが待機する。ICS 2024のGPUベッセル関数論文（arxiv:2409.08729）は、**入力を計算ブランチ別にソート**する手法で45倍の高速化を達成しており、Coulomb関数にも直接適用可能。

### レジスタ使用量の見積もり

| 構成 | レジスタ/スレッド | 占有率 |
|------|-----------------|--------|
| Numerov単独 | ~20–28 | ~80–100% |
| Numerov + 実数Coulomb | **~40–48** | ~50–62% |
| Numerov + 複素Coulomb | **~52–68** | ~37–48% |

SM当たり65,536レジスタ（Ampere/Hopper共通）で、48レジスタ/スレッドなら約1,365スレッド/SM（62.5%占有率）。**`__launch_bounds__`** と **`--maxrregcount`** で制御可能。50–60%の占有率は計算バウンドカーネルでは十分許容範囲。

### 事前計算テーブル方式 vs オンザフライ計算方式

| 要素 | テーブル方式 | オンザフライ方式 |
|------|------------|----------------|
| メモリ | 30×50×500グリッド: **24 MB**（十分小さい） | 追加メモリなし |
| 精度 | 補間誤差あり（テクスチャは9bit精度で不適格、`__ldg()`推奨） | 完全精度 |
| 柔軟性 | パラメータ範囲固定 | 任意パラメータ対応 |
| コンシューマGPU（FP64:FP32=64:1） | ✅ **強く推奨** | ❌ FP64スループット不足 |
| HPC GPU（A100/H100、FP64:FP32=2:1） | 可 | ✅ 競争力あり |

**既存のGPU Coulomb関数実装は存在しない**（2026年3月時点で確認）。HPRMAT (arxiv:2512.11590, 2025年12月) はGPU R行列計算で9–18倍高速化を達成したが、Coulomb関数はCPU側で計算している。**推奨実装順序**: Phase 1でテーブル方式（1–2週間）→ Phase 2でオンザフライ `__device__` 関数（4–8週間）→ Phase 3でハイブリッド方式。

## RQ-09: CUDA Cカーネルのhipify互換設計

### hipify-clang変換可能範囲

CUDA Runtime/Driver API、cuBLAS→hipBLAS、cuSOLVER→hipSOLVER、cuFFT→hipFFT、cuRAND→hipRAND、CUB→hipcubの自動変換に対応。**CUDA 12.9.1まで**サポート。HACCコード（15,000行）で95%が自動変換成功。**変換不可**: ビルドスクリプト、ユーザー定義の"cuda"文字列含む関数/マクロ、HIP等価のないサードパーティライブラリ。

### Warp-level intrinsicsのHIP対応

**ROCm 7.0以降**: `__shfl_sync`, `__ballot_sync`, `__any_sync`, `__all_sync` の `_sync` 変種が**デフォルトで利用可能**（大きな改善）。AMD wavefrontサイズは64（GCN/CDNA）vs NVIDIAワープサイズ32であるため、**マスク型は `unsigned long long`（64bit）** を使用する必要がある。`HIP_ENABLE_EXTRA_WARP_SYNC_TYPES` マクロ定義でdouble型シャッフルも有効化可能。

### atomicAdd(double)のHIP対応

**サポートされている**が、AMDではCompare-And-Swap (CAS) ループで実装。`-munsafe-fp-atomics` フラグでハードウェアRMW命令を生成可能だが、精度面の副作用あり。科学計算では**階層的リダクション**（shared memory → warp → block → atomic）でcontentionを最小化すべき。

### hipify変換不可能なCUDA固有機能

| 機能 | HIP状況 |
|------|--------|
| **動的並列処理** | ❌ 非対応（カーネルからカーネル起動不可） |
| **WMMA/Tensor Core** | ❌ 直接非対応（rocWMMAライブラリ必要） |
| **Surface関数** | ❌ 非対応 |
| **Cooperative Groups** | △ 部分対応（基本的なスレッドブロック同期のみ） |
| CUDA Graphs | ✅ 対応 |

### rocBLAS/rocSOLVERの複素batched LU分解

**rocsolver_zgetrf_batched** および **rocsolver_zgetrs_batched** が**完全にサポート**されている（s/d/c/z全精度、batched/strided_batched両方）。npvt（ピボットなし）変種も利用可能。hipBLASはrocSOLVERにリンクしてLAPACK機能を公開する。

### CubeCLのFP64評価

CubeCLの `Float` トレイトは f16/tf32/f8/flex32 が文書化されており、**f64は第一級型として公開されていない**。WebGPU標準がf64をサポートしないことが根本的制約。**科学計算（FP64必須）にはCubeCLは非推奨**。HIP/CUDA直接利用 + hipify、あるいは Kokkos/SYCL が適切な選択肢。

## 結論と今後の実装への指針

RQ-01のCOULCCアルゴリズムについては、CF1/CF2の完全な数式、修正Lentz法の擬似コード、6つの計算領域の境界判定基準、Wronskian結合公式をすべて特定した。**Rustでの実装はこれらの数式から直接コーディング可能**な水準の情報が得られた。RQ-02のRIPL-3フォーマットは列位置・FORMAT文字列まで特定済みであり、パーサー実装に直結する。RQ-06のcudarc v0.19のAPI変更（CudaDevice → CudaContext+CudaStream）は設計への影響が大きく、batched zgetrfはcuSOLVER経由が推奨される。RQ-09のhipify互換性については、ROCm 7.0以降でwarp intrinsicsの互換性が大幅に改善されており、rocSOLVERが複素batched LUを完全サポートしていることから、**CUDA/ROCm両対応の設計は十分実現可能**である。CubeCLはFP64非対応のため採用すべきではない。
